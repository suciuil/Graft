How this list is made

  • Every item is a line of the fork's commit messages, as written there: lines that start with Feature:, Bug-Fix:, Improvement: or Change request:. Commits without such a line are not listed. Such lines added later to a commit as a git note (refs/notes/changelog) count as part of its message.
  • The items of the hand-written report that came before this page was generated are kept too (changelog-legacy.json), each in the group it was listed in. A commit-message line one of them already covers is left out, so nothing is listed twice.
  • Items sit under the package build (npm run pack:bundle) that first shipped their commit, newest first. "Not yet bundled" items go into the next build. Items from before build dates were recorded sit under the date of their commit. A build made on Windows is named by its offline kit version a.b.c.d (the kit graft-a.b.c.d-win-x64.zip): a.b.c is the graft version inside it and d counts the kits of that graft version, starting at 0.
  • The area of an item only serves the filter below and is derived from words in its text. Items about the installer are also listed under "Packaging, installer, updates & CI", so the area counts can add up to more than the total.

Not yet bundled goes into the next npm run pack:bundle

Groovy uses the @bootswithdefer/tree-sitter-groovy v0.2.0 grammar and records calls without parentheses that end in a closure (items.collect { … }, bare Jenkins steps). .h files containing C++ are parsed and labelled as C++, and fall back to the C grammar when the C++ grammar is not installed.
