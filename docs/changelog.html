  • Bug fix, Improvement, Change request: only for functionality that upstream Graft already has.

  • FeatureCLI & configurationgraft about (also graft info) prints what graft is for, the upstream project homepage and the path of this fork changelog (docs/changelog.html), which ships inside the installed package. graft about home opens the homepage and graft about fork opens this changelog in the browser.first added 2026-11-04
  • FeaturePackaging & installerWindows installer and offline installer kit. Double-click START-HERE-install-graft.cmd, which runs install-graft-helper.ps1. It starts by explaining what graft is for, links the upstream project and shows the path and file:/// link of this fork changelog (shipped in the kit as changelog.html) without asking to open it. The kit is a single zip built from the project; packing it removes kits and packages left by earlier versions. The installer installs or upgrades from offline package files (also named like … - Copy.tgz or … (1).tgz). For Node.js it uses an offline zip placed next to it, or downloads the latest LTS and verifies its checksum. It reinstalls graft when the Node.js version changes. It fixes the user PATH without damaging existing entries, runs the graft it just installed, and warns if new terminals won't find graft and npm or if another graft in PATH would be used instead. It checks the LLM setup the way graft reads it (including Databricks and Anthropic-style endpoints), lists models and test-calls the chosen one. Finally it offers to download the public price list, which you can skip.first added 2026-10-20
  • Bug fixCLI & configurationOn Windows, console windows flashed up while an agent such as Claude Code used graft: every git, gh or npm call that graft made from a background job (such as the branch refresh after graft ask) or from a process without a console opened a window of its own. Graft now starts all its helper programs with their window hidden; only opening a page or file in the browser shows a window.

2026-10-20 first committed; build date not recorded

  • FeatureSavings & pricingPublic model price catalog (LiteLLM). A snapshot ships with graft and is refreshed on every build, keeping the old list when offline or when the download looks broken. graft prices update downloads a newer list, which is used when it is newer than the snapshot. graft prices status shows both lists and where each price comes from. Before downloading, graft prices update and the installer name the exact public price file and its GitHub address, confirm that nothing about you or your repo is sent, and show where the prices are stored. When a model can't be priced, the tally gets a ⚠️ Run the 'graft prices update' command — recommended (…) line.
  • FeatureCLI & configurationgraft api url, graft api key (hidden input), graft api provider and graft model save LLM settings as user-level environment variables, so every new terminal, IDE and MCP host sees them. They show the current value and its source, list the endpoint's models with a recommended pick, verify the endpoint after saving, and support --unset. build --deep uses the configured model when the gateway serves it and says which one it used and where that came from. When the latest model is picked automatically, a "1" in a name like "1adp" is not read as a version number. Interactive prompts show each typed key once.
  • FeatureLLM & deep buildgraft staleness [dir] shows the share of out-of-date summaries, whether a deep build is due, and the worst files. Supports --top, --no-refresh, --json and a per-repo split in workspaces.
  • ImprovementLLM & deep buildFailed build --deep runs end with a "How to fix it" block naming the setting to change (GRAFT_BASE_URL, GRAFT_API_KEY, GRAFT_MODEL) and listing available models. Workspace builds print it once for all child repos.
  • ImprovementLLM & deep buildLLM calls trust the operating system's certificate store, so corporate gateways and TLS-inspecting proxies work without NODE_EXTRA_CA_CERTS (Node 22.19+/24.5+; GRAFT_SYSTEM_CA=0 turns it off).
  • ImprovementCLI & configurationgraft --help is an A→Z command list with a plain-language description, arguments, options and examples for each command. graft <command> --help and graft help <command> print the same entry. Unknown commands get a "Did you mean…?" suggestion, and graft --model x without a command gives a short error.
  • ChangePrivacyTelemetry is permanently disabled. Nothing is recorded or sent, and it cannot be turned on. graft telemetry enable refuses, the init usage-stats row and first-run notice are gone, and npm postinstall no longer records an install event. graft telemetry is not listed in graft --help. README and TELEMETRY.md are updated.

2026-08-19 first committed; build date not recorded

  • FeatureLanguagesXML support for .xml, .config, .csproj, .vbproj, .fsproj, .props, .targets, .nuspec, .resx and .xaml. XML is indexed structurally but never sent to the AI: --deep skips it and check does not report it as pending. The Windows parser binary is bundled, so no compile step is needed.

  • FeaturePackaging & installerSelf-contained npm package and offline bundle (npm run build:grammars, npm run pack:bundle) with all optional native grammars and runtime dependencies. Prebuilt Windows bindings for all 19 local tree-sitter grammars ship under vendor/, so a machine with only graft checked out can build. Parsers too new for graft's runtime (ABI 15) are regenerated. Grammar files held open by a running graft don't block the build. Bundling works when allow-scripts is set in a user or global .npmrc. Grammars left out on purpose (such as the local Kotlin grammar) are reported as "not vendored". Installation shows fewer false warnings.
  • Bug fixAgent integrationsClaude Code helpers could use an older graft install that appeared earlier in the lookup list. They now pick the highest installed version and only call npm root -g when cheaper lookups fail.

2026-08-18 first committed; build date not recorded

  • FeatureLanguagesDepth-tier support (symbols, calls, inheritance, imports) for C#, Groovy, PL/SQL, C and C++, using optional native grammars. PL/SQL also covers SQL DDL tables and views, procedures called without arguments, and calls through a package or schema (pkg.proc, schema.pkg.proc).
