Languages & parsing upstream indexes TypeScript, TSX, Python, Go, Java, Kotlin, Swift, PHP and R

  • FeatureDepth-tier support (symbols, calls, inheritance, imports) for C#, Groovy, PL/SQL, C and C++, using optional native grammars. PL/SQL also covers SQL DDL tables and views, procedures called without arguments, and calls through a package or schema (pkg.proc, schema.pkg.proc). Groovy uses the @bootswithdefer/tree-sitter-groovy v0.2.0 grammar and records calls without parentheses that end in a closure (items.collect { … }, bare Jenkins steps). .h files containing C++ are parsed and labelled as C++, and fall back to the C grammar when the C++ grammar is not installed.
  • FeatureBreadth-tier support for CSS, SCSS, HTML, C# Razor, JSON, YAML, Markdown and CSV.
  • FeatureXML support for .xml, .config, .csproj, .vbproj, .fsproj, .props, .targets, .nuspec, .resx and .xaml. XML is indexed structurally but never sent to the AI: --deep skips it and check does not report it as pending. The Windows parser binary is bundled, so no compile step is needed.
  • FeatureCMake support: CMakeLists.txt and *.cmake.
  • FeatureBash support (.sh, .bash, .bashrc, .bash_profile): functions, calls between them, and source / . as imports resolved to in-repo scripts.
  • FeaturePerl support (.pl, .pm, .t): packages and subs, $self->m() and Pkg->m() calls resolved through the package and through use parent, use base and @ISA, and use/require as imports resolved to in-repo .pm files.
  • FeatureMake support: Makefile, makefile, GNUmakefile, *.mk, *.mak.
  • ImprovementKotlin .kts files (Gradle scripts) are included in the concept map built by --deep.
  • ImprovementA locally built Kotlin grammar (v0.4) is used when available, which parses more accurately than the registry version.
  • Bug fixKotlin inheritance edges were missing for superclasses (: Base(1)), delegated interfaces (: Runnable by impl) and qualified types (: com.acme.Base()).
  • Bug fixOne-line Kotlin objects (object Keys { val A = "a" }) were misread as infix calls, so their members appeared as top-level functions.

LLM providers, gateways & build --deep

  • FeatureDatabricks AI Gateway provider. Claude, OpenAI, Qwen/open models and databricks-* serving endpoints are routed automatically by model id. Databricks error messages are parsed correctly. graft model lists the GPT models the gateway serves, using checks that spend no tokens and skipping models that only support the Responses API. GPT models without a gateway service id work, and a model refused with "rate limit set to 0" is retried under its other name. Missing or rejected tokens point to where a personal access token is generated. A deep build asks for the key only once and reuses the model list it already fetched.
  • FeatureLLM Incubator gateway provider, with Bearer auth through ANTHROPIC_AUTH_TOKEN and ANTHROPIC_BASE_URL. It needs a base URL (GRAFT_BASE_URL or --base-url) and gives a clear error without one.
  • Featuregraft build --deep --force re-summarizes every file and symbol and ignores earlier results. If a forced call fails, the previous summary is kept. --force without --deep stops with a clear message.
  • Featuregraft effort views or sets the thinking effort the model uses in build --deep.
  • FeaturePause and resume when the AI relay runs out of balance. The build waits until the balance is refilled and then continues instead of failing. The error says "relay balance exhausted" rather than "provider rejected the API key".
  • FeatureStale-summary notice. When more than a threshold of the AI summaries (10% by default) is out of date or missing, every CLI query (on stderr) and every MCP tool result (at the end) carries a line recommending graft build --deep. Agents relay it under the savings tally as ⚠️ Run the 'graft build --deep' command — recommended (…) and are told never to run the deep build unasked. graft deep-threshold shows, sets or resets the threshold (0–100).
  • Featuregraft staleness [dir] shows the share of out-of-date summaries, whether a deep build is due, and the worst files. Supports --top, --no-refresh, --json and a per-repo split in workspaces.
  • FeatureFix the endpoint on the spot. When the endpoint rejects the API key or can't be reached, including during a deep build, graft offers to change the endpoint URL and/or the key so the re-run works.
  • FeatureChoose between a provider's endpoint and a custom URL. If a provider with its own endpoint (Anthropic, OrcaRouter) is set together with a different custom URL, graft asks which to use. It remembers the answer until the provider or URL changes, and also asks right after graft api provider.
  • ImprovementAutomatic connection and model fallbacks: the /v1 path suffix is added or removed as needed, provider-prefixed model names are retried as bare IDs, and graft switches wire protocol when an endpoint rejects a request.
  • ImprovementMore reliable with models that are strict about tool calls. Models that refuse forced tool calls or can't turn reasoning off are handled on both the OpenAI and the Anthropic paths, and replies made of text and reasoning parts are accepted.
  • ImprovementFailed build --deep runs end with a "How to fix it" block naming the setting to change (GRAFT_BASE_URL, GRAFT_API_KEY, GRAFT_MODEL) and listing available models. Workspace builds print it once for all child repos.
  • ImprovementLLM calls trust the operating system's certificate store, so corporate gateways and TLS-inspecting proxies work without NODE_EXTRA_CA_CERTS (Node 22.19+/24.5+; GRAFT_SYSTEM_CA=0 turns it off).
  • ImprovementWhen no endpoint URL is set and the provider has no default, graft says so clearly instead of silently contacting api.openai.com.
  • Bug fixSummaries failed on large files and files with many symbols. Requests are now batched, batches split automatically at the output token limit, and the source window is focused on the target definitions.
  • Bug fixOne failing concept-synthesis batch aborted the whole build --deep. Finished batches are now checkpointed, so a re-run only calls the AI for the missing ones.
  • Bug fixbuild --deep discarded good results when a model echoed the whole target description back instead of the plain ID.
  • ChangeThe default model is claude-haiku-5-5 instead of claude-sonnet-5-5 on every provider: build --deep, graft init (look-back, skill naming, PR review), help and examples. Model recommendations prefer Claude Haiku, then Claude Sonnet, then Gemini Flash, then GPT terra.
  • ChangeWhen no provider or base URL is configured, the Databricks AI Gateway is the default endpoint.

Token savings, pricing & model detection

  • FeatureAgents report the model they run on through a --agent-model CLI flag and an optional model parameter on every MCP tool. MCP calls keep their state separate, so concurrent requests don't mix. Agent instructions and MCP parameter descriptions ask for the model ID on every call, with specific guidance for GitHub Copilot in IntelliJ IDEA so it doesn't guess.
  • FeatureModel detection from host session records when the agent doesn't report a model: Kilo Code (including forks, VS Code Insiders installs, paired models and subagents, and shells started by Kilo's agent), VS Code / GitHub Copilot, and GitHub Copilot in JetBrains IDEs (including the locked session store on Windows). The agent's own report takes priority, except that a router family name (gpt-5) is refined to the precise model the host recorded. With several chats open, a host record is only used when the sessions agree or exactly one was written during the current turn. Otherwise tokens are shown without a price. Repos and VS Code workspaces opened through a junction or symlink are recognised, as are Kilo sessions not yet saved to Kilo's main database file. Kilo turns are not priced at the model of a Copilot chat in the same VS Code window, and Kilo and Copilot calls are not filed under the last Claude Code model in repos where Claude Code once ran. When one turn used several models (for example a planning phase on a different model), savings are shown per model with a combined total.
  • FeatureLifetime savings ledger and graft savings: cumulative tokens and dollars saved per model, for all time, a year, a month or a day. graft savings --all totals every repo graft was used in. Earlier repos are found by a one-time, read-only scan of the folders remembered by Claude Code, Kilo, VS Code, Cursor, Windsurf, VSCodium, JetBrains IDEs and Codex (--discover / --no-discover). One model spelled differently (punctuation, casing, provider prefixes, Databricks service ids and endpoint names) is kept as one row. If the savings file can't be read (for example an online-only OneDrive file), the saving is skipped with a warning instead of the history being lost, and an unreadable or corrupted file is set aside as a backup.
  • Featuregraft models and a multi-model estimate table. When the running model can't be identified (for example in Kilo Code or MCP sessions), savings are estimated for every model the host has configured. The table is a fenced ASCII box with right-aligned amounts. When a call is priced, agents report one plain line instead of a table.
  • FeaturePublic model price catalog (LiteLLM). A snapshot ships with graft and is refreshed on every build, keeping the old list when offline or when the download looks broken. graft prices update downloads a newer list, which is used when it is newer than the snapshot. graft prices status shows both lists and where each price comes from. Before downloading, graft prices update and the installer name the exact public price file and its GitHub address, confirm that nothing about you or your repo is sent, and show where the prices are stored. When a model can't be priced, the tally gets a ⚠️ Run the 'graft prices update' command — recommended (…) line.
  • FeatureStale agent-instructions warning under the savings tally: ⚠️ Run the 'graft init' command — recommended (…) appears when installed instruction files differ from what the running version would write.
  • ImprovementThe built-in price table covers more models: GPT-5.6, GPT-6 Astra/Sol/Luna, GPT-6.1 Sol, Gemini 3.7/3.8 and 2.5/3.x, Claude Opus 5.5 ($4/Mtok input, 0.05× cache read) and Opus 4.8 fast mode, Grok 4.5–4.7, Kimi K3 and K2.7, MAI-Code-1.1-Flash, DeepSeek and more. Model names are matched case-insensitively.
  • ImprovementSavings reports show where the price came from and which model was used, or why tokens could not be priced. They use readable model names ("Claude Opus 5") instead of routing IDs (vertex_ai/claude-opus-5).
  • Bug fixToken counts were unreadable on non-English locales ("1970 tokens saved" printed as "1.970").
  • Bug fixModel IDs with a provider prefix (anthropic/, azure/, …) were not priced.
  • Bug fixSavings were not tracked when CLI retrieval commands ran directly in a terminal.
  • Bug fixThe savings line was cut off in large outputs. It is now placed at the end of outputs over 20,000 characters so hosts that keep only the terminal tail still show it.
  • Bug fixOutput templates and agent instructions put quotation marks around the tally, so agents quoted it in their replies.
  • Bug fixClaude Opus 5.5 matched the Claude Opus 5 price rule, which overstated costs and savings.
  • ChangeSavings are priced at the coding agent's model, not at the enrichment model (GRAFT_MODEL). Dollars are only shown for a model confirmed for that turn; otherwise raw token counts are shown.

Agent integrations & instructions

  • FeatureKilo Code support.
  • FeatureTool-call gate for Claude Code and the Codex family. Wasteful tool calls are redirected to the matching graft command instead of only being advised against.
  • ImprovementEvery agent gets the tool rules stated as rules: literal search → graft grep, "what's in this file" → graft skeleton, "who calls this" → graft callers. This covers Cursor, Kilo Code, Kiro, Windsurf, Gemini, Copilot, Codex/AGENTS.md, Grok, Hermes and AdaL.
  • Improvement"Verify before you assert" rules for every host and skill: agents check repo facts with graft queries instead of guessing.
  • ImprovementInstructions for hosts that can't run commands (Copilot Ask mode, read-only modes): use graft's MCP tools or read the graft/ files, never invent a savings line, and end with a fixed "switch to Agent mode" notice. Applied to all agents, the Claude/AdaL/Grok skill and graft/INDEX.md.
  • ImprovementInstruction templates explain how to run the CLI on every platform (plain graft on Windows too, with an npx fallback).
  • Bug fixAgent instruction files in existing repos were not refreshed after prompt edits unless the package version changed. Wiring now compares content fingerprints.
  • Bug fixInstruction files stayed outdated after switching branches or merging. They are now checked on disk and restored when they drift.
  • Bug fixClaude hooks and the status line failed under some shells. They now run under any shell, including cmd.exe and PowerShell on Windows.
  • Bug fixClaude Code helpers could use an older graft install that appeared earlier in the lookup list. They now pick the highest installed version and only call npm root -g when cheaper lookups fail.

CLI & configuration

  • FeatureExclude folders from graft commands with --excludeDir / the exclude-dirs setting.
  • FeatureDefault .graft/config.json written by graft init. Missing default settings are added to an existing file. No empty connection details are written.
  • Featuregraft config lists and changes .graft/config.json settings (exclude-dirs, include-dirs, follow-submodules, follow-nested-repos) without editing JSON. Takes --repo <dir> and has per-setting help.
  • Featuregraft init and graft build follow VS Code .code-workspace files. graft init offers to wire and build each listed folder. graft build can build all listed folders, including folders outside the current directory, and remembers the choice. Both are controlled by --workspace <file> and --no-workspace. Without a terminal or with --yes, a workspace is never assumed.
  • Featuregraft api url, graft api key (hidden input), graft api provider and graft model save LLM settings as user-level environment variables, so every new terminal, IDE and MCP host sees them. They show the current value and its source, list the endpoint's models with a recommended pick, verify the endpoint after saving, and support --unset. build --deep uses the configured model when the gateway serves it and says which one it used and where that came from. When the latest model is picked automatically, a "1" in a name like "1adp" is not read as a version number. Interactive prompts show each typed key once.
  • Featuregraft languages lists every indexed language and its support level on this install: full, broad, symbols, structural, file-only or skipped.
  • Featuregraft issues opens the issue tracker in the browser and also prints the address.
  • Featuregraft about (also graft info) prints what graft is for, the upstream project homepage and the path of this fork report, which now ships inside the installed package. graft about home opens the homepage and graft about fork opens this report in the browser.
  • Improvementgraft --help is an A→Z command list with a plain-language description, arguments, options and examples for each command. graft <command> --help and graft help <command> print the same entry. Unknown commands get a "Did you mean…?" suggestion, and graft --model x without a command gives a short error.
  • ImprovementIn the graft init picker, Enter selects the highlighted agent, and an agent you unticked stays unticked.
  • Improvementgraft build no longer ends with a success tick when it finds no files. It shows a warning and, when it can tell, explains why (for example, the folder is ignored by the repo it sits in).
  • Bug fixRe-running graft init (picker or --yes) removed instructions of agents already wired in the repo, for example ones only a teammate's machine has. They are now kept and shown in the picker.

Privacy / no-cloud policy

  • ChangeTelemetry is permanently disabled. Nothing is recorded or sent, and it cannot be turned on. graft telemetry enable refuses, the init usage-stats row and first-run notice are gone, and npm postinstall no longer records an install event. graft telemetry is not listed in graft --help. README and TELEMETRY.md are updated.
  • ChangeTrail cloud (Trail workspace) is permanently disabled. Nothing is uploaded. TRAIL_CLOUD, TRAIL_URL and ~/.trail/cloud.json are ignored, trail login and trail workspace add refuse, and trail status has no workspace row.
  • ChangeNo-cloud policy (docs/no-cloud-policy.md and agent instruction files). Users can't switch on anything that sends data to a cloud or other third party through settings, flags, commands or toggles. New upstream features that send data out stay disabled until the repository owner approves them, and each decision is recorded.

Packaging, Windows installer, updates & CI

  • FeatureSelf-contained npm package and offline bundle (npm run build:grammars, npm run pack:bundle) with all optional native grammars and runtime dependencies. Prebuilt Windows bindings for all 19 local tree-sitter grammars ship under vendor/, so a machine with only graft checked out can build. Parsers too new for graft's runtime (ABI 15) are regenerated. Grammar files held open by a running graft don't block the build. Bundling works when allow-scripts is set in a user or global .npmrc. Grammars left out on purpose (such as the local Kotlin grammar) are reported as "not vendored". Installation shows fewer false warnings.
  • FeatureWindows installer and offline installer kit. Double-click START-HERE-install-graft.cmd, which runs install-graft-helper.ps1. It starts by explaining what graft is for, links the upstream project and shows this fork report (shipped in the kit as fork-report.html), offering to open it in the browser. The kit is a single zip built from the project; packing it removes kits and packages left by earlier versions. The installer installs or upgrades from offline package files (also named like … - Copy.tgz or … (1).tgz). For Node.js it uses an offline zip placed next to it, or downloads the latest LTS and verifies its checksum. It reinstalls graft when the Node.js version changes. It fixes the user PATH without damaging existing entries, runs the graft it just installed, and warns if new terminals won't find graft and npm or if another graft in PATH would be used instead. It checks the LLM setup the way graft reads it (including Databricks and Anthropic-style endpoints), lists models and test-calls the chosen one. Finally it offers to download the public price list, which you can skip.
  • Bug fixOn Windows, running npm for the update check and graft upgrade, checking whether graft is installed, and waiting on a file lock did not work reliably.
  • ChangeThe update check and graft upgrade use the company npm registry instead of the public npm registry. Installing graft adds that registry to the user .npmrc.
  • ChangeThe upstream GitHub CI workflows are disabled in the fork; they stay in the repository but do not run.
